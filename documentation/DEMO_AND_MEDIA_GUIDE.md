# Руководство по визуализации и демо-материалам на GitHub

В этом документе собраны проверенные практики, шаблоны и стандарты для демонстрации возможностей приложения **Kola («Шестой школьный день»)** на GitHub с помощью GIF-анимаций, WebP, видео и интерактивных блоков.

---

## 1. Проблема отображения демо на GitHub и её решение

### Ограничения стандартного GitHub Markdown:
1. **Тяжёлые GIF-файлы**: GIF 1080x2400 на 15 секунд может весить 30–70 МБ, что приводит к долгой загрузке README и превышению лимитов репозитория.
2. **Артефакты палитры GIF**: GIF ограничен 256 цветами, из-за чего градиенты и неоновые акценты темы приложения (HackTheme) могут выглядеть зернистыми.
3. **Вертикальный формат смартфонов**: Мобильный экран 9:19.5 занимает слишком много места по вертикали, если вставлять его в исходном размере.

### Рекомендуемые решения:
- **Анимированный WebP или сжатый GIF** с шириной не более 320–360px для мобильного экрана.
- **Отображение в виде HTML-таблицы (Side-by-Side)**: 2–3 устройства рядом (например: «Ученик» | «Учитель» | «Администратор»).
- **Сворачиваемые секции `<details><summary>`**: не перегружают первый экран README и открываются пользователем по желанию.
- **Хостинг медиа**: загрузка в специальную ветку репозитория, папку `documentation/assets/gifs/` (с Git LFS при необходимости), либо как постоянные ассеты GitHub Release / Issue.

## 2. Размещение файлов в репозитории

Рекомендуемая структура хранения медиа-файлов:

```text
documentation/
└── assets/
    ├── badges/         # Кастомные бейджи и иконки
    ├── architecture/   # Экспортированные SVG/PNG диаграммы
    ├── mockups/        # Статичные мокапы экранов (PNG/WebP)
    └── gifs/           # Записанные скринкасты и демонстрации
        ├── auth-flow.webp
        ├── activity-create.webp
        ├── voting-quorum.webp
        ├── teacher-moderation.webp
        ├── admin-approval.webp
        └── qr-scanner.webp
```

> [!TIP]
> GitHub отлично воспроизводит анимированные `.webp` файлы! Они в 3–5 раз легче аналогичных `.gif` и поддерживают 24-битный цвет без зернистости.

### Шаблон 2: Интерактивный аккордеон со стадиями жизненного цикла

Для подробного описания каждого этапа без загромождения главного экрана:

```html
<details>
<summary><b>🎬 Посмотреть видеодемонстрацию: Этап голосования и кворум (Нажмите, чтобы развернуть)</b></summary>
<br>

<p align="center">
  <img src="documentation/assets/gifs/voting-quorum.webp" alt="Процесс голосования" width="320px" style="border-radius: 16px; border: 1px solid #333;" />
</p>

#### Что происходит на этом этапе:
1. Мероприятие переходит в статус `ON_VOTE`.
2. Одноклассники видят карточку в ленте и нажимают кнопку **«Я иду!»**.
3. Индикатор прогресса в реальном времени заполняется до порога кворума.
4. При достижении порога заявка автоматически уходит на согласование администрации школы.
```

## 4. Пошаговые сценарии (Storyboards) для записи демо

Для записи наглядных демонстраций рекомендуется подготовить следующие 5 ключевых сценариев:

| Сценарий | Роль | Входные данные | Целевые действия для записи | Длительность |
| :--- | :--- | :--- | :--- | :--- |
| **1. Авторизация Schools.by** | Любая | Учетная запись Schools.by | Ввод логина/пароля -> автоматический парсинг профиля -> выбор класса -> вход в шлюз | 5–8 сек |
| **2. Инициатива ученика** | Ученик (PUPIL) | Лента мероприятий | Нажатие «+» -> заполнение названия, категории, описания -> прикрепление фото -> установка кворума -> отправка | 10–12 сек |
| **3. Модерация учителем** | Учитель (TEACHER) | Экран заявок | Просмотр списка заявок своего класса -> открытие деталей -> одобрение или отклонение с комментарием | 6–8 сек |
| **4. Голосование и Кворум** | Ученики класса | Карточка мероприятия | Нажатие кнопки «Я иду!» несколькими участниками -> прогресс-бар кворума до 100% -> смена статуса на «У администрации» | 8–10 сек |
| **5. QR-Шеринг и Сканер** | Ученик | Детали мероприятия | Генерация QR-кода на экране -> сканирование с другого устройства камерой -> мгновенное открытие экрана | 6–8 сек |

## 5. Инструкция по записи и конвертации материалов

### Вариант А: Запись через Android Studio
1. Подключите устройство или запустите эмулятор.
2. В окне **Logcat / Running Devices** нажмите иконку **Screen Record**.
3. Запишите сценарий в формате `.mp4`.
4. Сконвертируйте в оптимизированный WebP/GIF с помощью `ffmpeg`:

```bash
# Конвертация в оптимизированный анимированный WebP (наилучшее качество и вес):
ffmpeg -i demo_input.mp4 -vf "scale=360:-1:flags=lanczos,fps=24" -lossless 0 -compression_level 6 -q:v 70 -loop 0 documentation/assets/gifs/demo_output.webp

# Либо конвертация в сжатый GIF с двухпроходной палитрой:
ffmpeg -i demo_input.mp4 -vf "fps=20,scale=360:-1:flags=lanczos,split[s0][s1];[s0]palettegen[p];[s1][p]paletteuse" documentation/assets/gifs/demo_output.gif
```

### Вариант Б: Запись через ScreenToGif / CleanShot
1. Установите область захвата точно по границам окна эмулятора.
2. Частота кадров: **20-25 FPS** (достаточно для плавной Compose-анимации).
3. Примените обрезку системных панелей (статус-бар и панель навигации можно оставить для реализма).
4. Экспортируйте с максимальным сжатием.
